# 正式专家审阅工作台

独立入口：`https://www.huanyumedical.com/expert-review/`。官网、医院后台和已通过原型 `/expert-review-preview/` 不变。

## 使用流程

1. 后台开通账号后登录；专家可查看全部已生成的专业/可行性报告，不做病例分配。
2. “用户提交资料”查看脱敏填写原文。上传资料区显示病历原件分页预览，自动解析摘要与原件明确区分。
3. 原件第一次使用前由管理员/资料处理人员打开“准备脱敏预览”，逐页框选姓名、证件、联系方式、条码等，保留医学内容，确认后发布不可逆遮盖副本。普通专家不能访问未脱敏原件。
4. 保留正式报告排版，点击模块或内容块进行认可、修改、批注、补充、依据不足、不适用；记录原因、建议文案、依据及引用资料。保存草稿、确认模块后提交；已提交记录锁定，原报告不覆盖。
5. 当前阶段，勾选为“可复用知识”的医学修改/补充，在完成审阅提交后直接发布入库；生成器以本地语义向量与 BM25 混合检索，经疾病/指标/分期等硬条件和现有医疗模型适用性核验，按报告模块供新报告参考，历史报告不变。管理员或原专家可撤回错误知识。
6. 专人确认是后续功能，状态/权限/模式开关已预留，但当前不作为阻塞。后台可切回需确认模式；待确认、草稿、撤回及不适用知识仍不参与生成。
7. 新报告有引用记录时可展开查看实际提供项的模块、版本、相关分和匹配原因；相关分不是医学置信概率，提供参考不代表模型已采纳。无合格匹配/核验故障时不强行引用，也不自动训练模型。

## 开发与构建

```sh
npm run expert:dev
npm run expert:build
```

开发默认 `http://127.0.0.1:5190/expert-review/`，代理 `/api/expert/` 到 `127.0.0.1:3000`。可用 `EXPERT_API_TARGET` 指定本地测试后端。正式部署采用同域 Nginx 反向代理，不把账号/密码或患者数据写入前端构建。

支持 JPG/PNG 等图片、PDF、UTF 文本分页预览。其他格式/编码及历史缺失原件明确拒绝预览，需要补充图片/PDF；禁止以OCR摘要冒充完整原件。

测试阶段按用户要求保留简单测试账号，界面显示风险提示。推广前应更换强密码并为不同操作人员建立独立账号，避免共用账号无法区分责任。

后端流程、角色、数据门禁见 `../../Studio-huanyu-Server/docs/expert-review-flow.md`。
