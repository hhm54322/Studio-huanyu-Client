## 一、竞品对比得到的可借鉴能力

| 能力 | 竞品做法 | 寰宇应形成的能力 |
| --- | --- | --- |
| 医院/医生比较 | 医院卡同时展示评分、评价数、项目价和详情；医生卡连接视频预约 | 让用户能按病种、城市、专科、语言、价格和可约方式比较，并直接进入咨询/预约 |
| 收费解释 | 协调服务分套餐，明确包含项、排除项、限制条件，医疗费另计 | 把专家服务、平台协调、翻译陪诊、医院医疗费、差旅住宿拆开显示，统一币种、有效期和退款规则 |
| 远程问诊 | 医生资料、经验、视频价格和预约动作放在同一链路 | 医生卡补齐时长、时区、平台、翻译、病历要求、取消/改期、问诊后书面意见与追问范围 |
| 病种与流程 | 从项目/专科进入医院和医生；把行前、预约、就诊、回国支持拆成步骤 | 统一为“初筛 → 医生复核 → 书面方案/报价 → 预约赴华 → 到院就诊 → 回国随访”，每步写清资料、负责方、耗时和交付物 |
| 案例与信任 | 患者故事有独立详情；价格和资料标来源/更新时间；区分协调方与临床方 | 建立授权、脱敏、可核验的案例模板；所有数字、政策和服务承诺有来源、日期、适用范围和责任边界 |

## 二、修复优先级

### P0：先消除误导和合规风险

1. **签证/过境政策（01）**：撤下“M 字医疗签证”“S2 普遍适用于医疗陪护”等未经核实表达；区分普通签证、免签和 240 小时过境免签，补官方链接、核验日期、国籍/领区/家属条件。
2. **保险覆盖结论（02）**：仅选择保险公司时不得显示住院比例、CAR-T 覆盖或预授权天数；默认改为“待核验”，按保单、保障区域、既往症、适应症和预授权逐项核查。
3. **隐私与资料告知（03）**：提交前提供可访问的隐私政策和服务条款，说明收集目的、保存期限、接收方、删除入口；初筛移除非必要证件字段，并保留政策版本与同意记录。
4. **药品入境（43）**：撤下“自用、合理即可”“基本都能放行”等保证；按普通药、麻醉/精神药等类别补处方、数量、申报和官方查询来源，明确以海关实际要求为准。

P0 中，程序可以先把默认值、入口、告知和拦截逻辑改好；政策、保险规则、隐私文本和药品分类必须由业务/专业负责人提供并确认后才能上线。

### P1：补齐用户完成决策所需的信息

- **服务与联系方式（04、24、30、46）**：替换电话、微信、WhatsApp 占位和禁用链接；明确在线时段、响应时限、服务城市、提供方、限制条件、替代方案；把协调服务与医疗行为分开表述。
- **可用页面与导航（05、18、20、34、35）**：处理 `/visa`、`/equipment`、`/professional-report` 等停用地址；所有按钮和协议入口有真实去向或明确“尚未开放”；未知地址返回真正 404，手机菜单与桌面导航保持一致。
- **医院/医生资料（06、14、15）**：修正城市、院区和筛选映射；医生卡增加专科、院区、语言、问诊方式、价格/可约信息；评分必须有评价数量、来源和日期；医院端导航文字保持可见并有键盘焦点。
- **统计、医学证据和业务数据（07、08、16、17）**：建立统一指标表，区分签约资源、可协调资源、行业数据和平台数据；所有排名、感染率、培训比例、手术量、增长率、医院/患者数量有样本、区间、口径和来源；收入估算标明月/年、可调参数和“情景估算”性质。
- **保险、费用和牙科报价（09、10、11、44）**：删除无样本的成功率；费用按同术式/同耗材/同疗程列区间，注明币种、换算日期、医院层级和包含项；牙科拆分植体、基台、牙冠、影像、骨增量、赴华次数和停留时间；统一封顶预算、浮动估价和加项规则。
- **评估、案例和病种（12、13、42）**：初筛与深度评估分开，说明资料格式、大小、失败重试、回复时间和交付内容；病种目录数量与详情承诺一致；补 3–5 条获得授权的完整案例，展示时间线、预算差异、随访和个体差异，不把个案结果写成保证。
- **搜索与可访问性（19、21、22、25、28、33、40、41）**：生成有效 robots/sitemap；完善页面标题、正文、语义标题和读屏顺序；补语言版本；统一品牌标识；移除轮播 `XXX` 占位；FAQ 数量、目录、正文和页面入口一致；数据安全声明必须有可核验依据。
- **文章与工具包（45、26）**：逐篇修复残句、错序、章节混排和未完成提示；工具卡直接进入对应文章，摘要与正文一致，补来源、模板和更新时间；缺内容的卡片先下线或标注未开放。

### P2：在 P0/P1 稳定后做体验和工程优化

- 手机首页固定主要操作，轮播不承载唯一入口（23）。
- 首页按“评估—复核—报价—赴华—随访”重组重复营销内容，降低医生入口深度（29）。
- 对牙科、工具包、医生、医院和信任页按真实 CWV 测量继续拆包、延迟加载和清理冗余设计数据（27）。
- 医院端补真实脱敏功能图、API 版本/鉴权/错误码/限流/沙箱/SLA；没有真实联调前不宣称可用性（31）。
- 关于页补主体、团队角色、合作授权和服务城市的可核验资料；区分行业资源和直接合作（32）。
- 修复同排卡片标题基线和移动端标题断行，覆盖 390、768、1024、1280、1912 宽度（36、37）。

## 三、哪些可以直接改程序

以下项目不依赖新的业务事实，程序可以直接处理：

- 表单分步、必填校验、敏感字段最小化、隐私政策/服务条款入口、同意记录和上传失败重试。
- 保险结果默认“待核验”、未输入保单时不显示比例或覆盖结论。
- 停用页面替代提示、未知地址 404、真实链接占位校验、按钮无效状态和手机菜单。
- 医院城市筛选映射、医生/医院卡片字段布局、评分与评价数展示位、价格拆分组件、服务包包含/不包含结构。
- 费用/收入计算器的参数化展示、月/年口径标签、币种格式和报价日期字段。
- robots.txt、sitemap.xml、页面 meta、语义标题、读屏顺序、键盘焦点、对比度、轮播暂停与固定 CTA。
- 工具包文章入口、案例详情路由、病种—医院—医生关联、页面级状态、加载/空数据/错误态。
- 卡片对齐、移动端响应式、标题断行、图片占位、资源拆包、延迟加载、缓存和性能回归测试。

程序改动必须保留现有 Figma 结构和业务流程；涉及医疗判断、政策承诺或价格事实的地方只提供展示和校验能力，不在代码中自行编造默认值。

## 四、需要业务/专业方提供的内容

以下资料缺失时，程序只能先做“待核验/未开放”状态，不能自行补写：

1. **政策与合规**：签证/过境/药品官方链接、适用条件、核验日期；隐私政策、服务条款、保存期限、删除和投诉渠道；数据安全证明和备案信息。
2. **保险规则**：支持核验的保险公司/计划、保障区域、既往症和预授权核验流程；不得只给一个保险公司名称就推导报销比例。
3. **服务与收费**：每项服务的适用对象、交付、时长、语言、次数、包含/排除项、医疗费是否另计、报价有效期、加项、取消和退款规则；正式币种和收款主体。
4. **医院与医生**：城市/院区/科室/职称/语言/接诊方式/可约时段/价格区间；评分、评价授权、样本和更新时间；医院国际部门和可公开联系方式。
5. **业务统计与证据**：医院、患者、国家、认证、排名、培训、感染率、手术量、增长率和收入模型的原始记录、统计区间、去重规则和责任人。
6. **病种与案例**：首批核心病种、治疗范围、所需资料、风险与限制、医院/医生资源；患者授权、脱敏案例、治疗时间线、预算和随访记录。
7. **运营渠道**：真实电话、微信二维码、WhatsApp 账号、在线时段、响应 SLA、服务城市、翻译/陪诊/餐食/宗教支持的实际供应范围及院规限制。
8. **多语言与主体资质**：英文及其他语言的最终文案、公司主体/团队角色/合作授权/服务地点、可公开证照和合作关系边界。

## 五、建议的实施顺序与交付物

### 阶段 0：资料冻结与风险校准

交付：政策/保险/隐私/收费/服务边界确认表，统计口径表，医院医生字段模板。未确认内容统一标为“待核验”，不进入营销承诺。

### 阶段 1：P0 程序与内容闭环

交付：保险中性结果、隐私告知与同意、政策/药品来源入口、真实/停用地址处理、P0 回归清单。

### 阶段 2：P1 决策信息与转化链路

交付：医院/医生比较卡、服务收费说明、远程问诊入口、核心病种详情模板、初筛/深度评估流程、案例详情、FAQ/文章修订。

### 阶段 3：P2 体验与工程收尾

交付：手机 CTA、SEO/可访问性、工具包导航、医院端技术资料、团队与资质、响应式排版和性能报告。

每一项按“来源/更新时间/责任人/页面入口/程序验收”记录；内容未提供时不以占位数字或竞品数字替代。
