# 网站秒级打开与首屏无感加载方案

> 本文为2026-11-02的诊断/实施记录。最新缓存结果、付费建议和备案条件见[2026-11-03方案](site-speed-acceleration-20261103.md)；不以本文前序“未预热”“30天缓存”等历史状态作为现状。

## 当前诊断

2026-11-02 调整前的公网抽样：

- 首页 HTML 首字节约 0.86–1.06 秒，当前边缘客户端协商为 HTTP/1.1。
- HTML 设置为 `no-cache`，每次访问仍需回源或重新验证；当前公共 HTML 是空的 `#app`，主要内容要等 Vue/JS 挂载后才出现。
- 首页入口 JS gzip 后约 29KB，静态图片已使用 WebP，首图约 70KB 且可以命中 CDN；静态资源已有 30 天 immutable 缓存。
- CDN 已存在，但部分入口/JS 请求仍出现 MISS，复测中出现过一次连接重置。
- 当前源站回环响应很快、负载没有明显瓶颈，因此第一优先级不是升级 ECS。

## 目标

- 目标地区 CDN 热缓存 HTML 首字节 P75 ≤ 200ms，冷缓存 ≤ 800ms。
- 首屏文字和第一张主图在 1 秒级开始展示，主图解码不晚于首屏文字明显出现。
- 目标地区真实用户 LCP P75 ≤ 2.5 秒、INP ≤ 200ms、CLS ≤ 0.1。
- 公共静态资源命中率稳定，发布不产生旧哈希资源 404；API、病例资料、报告和审阅数据不进入公共缓存。

## 第一阶段：先改现有 CDN（收益最大）

1. 两个域名已开启边缘 HTTP/2，公网验证通过。HTTP/3/QUIC 尚未启用；当前只改源站 Nginx 不会改变 CDN 客户端协议。
2. 保留 Gzip。Brotli 对比测试未获得更小的传输体积，已关闭；协议和缓存命中仍是优化重点。
3. 对 `/`、公开患者路由和不含个人数据的 SPA HTML 设置边缘 `s-maxage=30–60s`、`stale-while-revalidate=300s`；浏览器仍可 `no-cache`。`/api/`、上传、报告、专家工作台、鉴权和用户资料路径禁止公共缓存。
4. 对哈希 JS/CSS/WebP/字体保持 `public,max-age=2592000,immutable`；发布前使用 CDN 预热首图、入口 JS/CSS、字体和主路由，发布后只刷新 HTML/版本入口。
5. 通过电信、联通、移动、香港、新加坡及主要海外地区分别测冷缓存/热缓存，记录 TTFB、LCP、INP、CLS、HIT/MISS、协议和错误率。

## 第二阶段：代码侧首屏改造

1. 首页当前只返回空 `#app`。将首屏 Hero/导航做构建期预渲染或 SSR，至少让首屏关键文字和背景在 JS 未完成前可见，再由 Vue 接管交互。
2. 当前首图 preload 使用低优先级；改为仅对当前首屏主图使用 `fetchpriority=high`，其余轮播图在首图完成后低优先级预热，继续保持 5 秒轮播规则。
3. 缩小首页首屏依赖：不要把下方 Figma 源树全部列入首屏 `modulepreload`；首屏只加载 Hero、页头、首个可见模块，其他模块在空闲时间或接近视口时加载。
4. 给主图和首屏模块写入明确宽高/`aspect-ratio`，使用 WebP/AVIF 的 `srcset` 和 `sizes`，避免移动端下载桌面 2 倍大图；图片 decode 后再淡入，加载期间使用同色背景或低清占位，避免白块和跳动。
5. 关键字体只预加载实际首屏使用的字重，非关键字重延后；继续保留 `font-display: swap`。
6. 首屏完成后再加载 ECharts、详情弹窗、长文和下方图片；不把全站图片一次性加载作为“加速”。

## 第三阶段：静态资源与跨地域扩展

- 流量增长或源站带宽成为瓶颈时，把公共图片、字体和哈希 JS/CSS 放到 OSS，CDN 以 OSS 为回源；病例资料和报告仍走鉴权链路。
- 只有目标海外地区动态 API、上传或会话链路持续慢时，才对单一域名/地区试点 DCDN 或 GA；不要同时叠加多套加速，避免无法归因。
- 只有在 CPU、内存、连接数或报告任务队列出现持续瓶颈时再升级 ECS，并将报告/AI 作业拆到独立 worker。当前证据不足以支持仅因图片加载慢而扩容。

## 验收与回滚

每次只改一类配置，保留原值和发布时间；用真实地区探测与 Chrome 冷/热缓存各跑 3 次，验收 TTFB、LCP、INP、CLS、协议、缓存命中和资源错误。出现错误率或地区延迟升高时，恢复上一条 CDN 规则并刷新受影响的公共 HTML 缓存。

CDN 边缘协议、缓存、Brotli 和预热需要阿里云 CDN 控制台权限；SSH 只能改源站，不能替代这些边缘配置。

### 后续公网复测（2026-11-02 09:21 UTC）

当前网络对每个 URL 独立请求 3 次，均使用有效证书校验，不绕过 TLS 验证。此处为 HTTP 请求耗时，不是浏览器首屏或 LCP；不能代表其他地区用户体验。

| 对象 | 实测结果 | 缓存状态 |
| --- | --- | --- |
| www 首页 HTML | TTFB 0.98–1.36 秒，中位数 1.26 秒 | 3 次均 MISS，`Cache-Control: no-cache` |
| 主域名 HTML | TTFB 1.32–4.12 秒，波动较大 | 3 次均 MISS |
| 入口 JS | 成功的 2 次约 0.76–0.85 秒，Gzip 约 29KB；另 1 次连接 reset | 成功请求均 HIT |
| 首页主图 | 约 71KB，完整下载 1.06–1.16 秒 | 3 次均 HIT |

HTTP/2 和 Gzip 已生效，静态文件缓存正常；公共 HTML 每次回源和链路波动仍是主要待处理项。下一步为限定公共页面 HTML 短时边缘缓存（先核对鉴权、Cookie 和响应内容）、完成可核验的预热、多地区链路测试，以及代码侧首屏预渲染。当前尚不能验收为稳定秒开。


### 首页短缓存试验与回滚（2026-11-02）

- 为 `www` 首页根路径创建条件 `public-root-html`，限定 URI `/`、GET、无 Authorization 和无 Cookie，并关联 60 秒 CDN 缓存。静态长缓存及 JSON 0 秒规则保留。
- 公网试验观察到根页面 `x-swift-cachetime: 60` 和 HIT；但携带测试 Authorization 的根请求也命中了已存公共框架，身份请求的预期绕过没有通过验证。实际框架不含任何病例/用户数据。没有调用真实业务接口或使用真实身份凭证。
- 已撤销该 60 秒配置并清理试验条件；不将此试验计作上线优化收益。后续应在源站对明确公共 HTML 设置可控的 `s-maxage`，并在需要时设置真正的鉴权绕过缓存机制，再重复验证。不能靠“只在写缓存时检查请求条件”推断读缓存也绕过。
- 连续复测 www 首页 TTFB 1.28–4.55 秒，主域名 1.01–2.91 秒，均含新建 TLS 连接耗时；链路与回源仍有波动，尚不能验收为稳定秒开。


### 本轮最终实施与停止边界（2026-11-02 15:30 UTC）

已发布 `20261102142806`。首页首屏拆分、提前请求、下方内容与图表延后已完成，本地慢网LCP中位1.97秒。公网图文显示差基本消除，但当前网络3次首屏为1.456/5.064/6.404秒，仍未达到稳定秒开；原始样本全部保留。

匿名首页/牙科60秒共享缓存已在源站与CDN落地；带Cookie/Authorization时源站返回private/no-store，CDN CacheKey按两头部隔离。CDN缓存规则状态成功，初版短缓存试验的失败及回滚记录仍保留。新加坡源站发起的CDN探测曾测得HIT约0.08秒；此结果只用于定位网络差异，不替代用户地区测量。其他路由及主域名未扩大公共HTML缓存范围。

两批共57项官方预热已核实100%完成（16+41，逐项匹配URL，无缺项）。HTTP/2、新证书、Gzip保留；两域名增加OCSP Stapling与边缘HTTP→HTTPS跳转（从默认改为强制HTTPS，保留路径与参数）。所有配置原值与变更后的DOM证据、HTTP响应及回滚资料均位于 `artifacts/deployment/20261102142806/`。

现阶段剩余问题集中在访问节点的连接与传输波动：缓存HIT仍有秒级TLS/传输等待，且部分连接在TLS阶段重置。控制台QUIC有独立计费入口，未启用；DCDN/全球加速、OSS迁移、ECS扩容也未购买或开通。建议先由云厂商依据留档节点IP、时间、EagleId与重置样本排障，再按实际用户地区试点加速；国内访问需评估中国内地节点接入条件。不能断言任何单项付费产品必然修复重置，也没有证据支持先扩容ECS。

本轮停止新增收费配置。未来仍可做预渲染或源树静态编译等独立架构优化，但当前最大的可测延迟位于代码执行前；不把本轮收敛写成程序永远没有优化空间。
