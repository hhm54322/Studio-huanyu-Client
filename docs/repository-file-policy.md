# 仓库文件保留规则

| 类别 | 本地 | Git |
| --- | --- | --- |
| 应用、正式专家工作台、接口、迁移、测试、构建/部署和可复用 QA 脚本 | 保留 | 保留 |
| 页面使用的图片、SVG、字体、Figma 运行数据和样式 | 保留 | 保留 |
| 开发规范、页面规格、模块覆盖、连接说明 | 保留 | 保留 |
| 原始 `.fig`、Layers/Dev 提取、基线 HTML、节点映射、资源清单和源锁 | 保留用于后续设计复核 | 忽略；运行时直接导入的 100 份 JSON/CSS 除外 |
| `artifacts/`、`docs/figma-verification/` 截图及比对结果 | 保留仍需使用的验收证据 | 忽略；文字差异清单除外 |
| 旧演示 `prototypes/`、用于基线的图片导出 | 保留用于产品讨论/复核 | 忽略；正式工作台共用的两个报告渲染器、一份样式以及后端测试依赖的脱敏样例除外 |
| 旧版通用图片 | 确认无用的删除；仍被本地 PPT 生成脚本引用的保留 | 本地 PPT 依赖忽略，正式页面资源保留 |
| `dist/`、缓存、压缩伴生文件、失效实验图片 | 可重新生成；失效实验删除 | 忽略 |
| 后端 `uploads/`、导出资料、日志和密钥配置 | 保留业务所需资料 | 忽略 |

`docs/figma-source/` 不是纯文档目录：页面直接导入其中部分数据，不能整目录删除或全部忽略。`.gitignore` 为这批实际依赖逐文件放行，资源路径仍保持不变；新增运行时导入也必须加入放行列表。牙科机构图片目前直接引用 PNG，应保留，不能因同时存在 WebP 而删除。

正式工作台还直接引用 `prototypes/expert-review/FreeReportPreview.vue`、`ProfessionalReportPreview.vue` 和 `workbench.css`，这三份共用代码必须随源码提交。后端审阅流程测试需要同目录的脱敏报告夹具 `samples.json`，也随源码保留；其余演示入口与数据准备脚本只保留本地。

`public/` 中仅用于旧设计提取、局部基线或本地演示且已确认没有应用消费者的资源使用逐文件忽略规则。正在使用的首页、牙科、医院、关于我们、保险、病例、病种和信任页图片/图标资源族整体随源码保留，覆盖动态路径与子状态。筛选时同时核对运行数据、动态路径和仓库外本地文档脚本，不能凭“未搜索到完整 URL”就删除文件。

## 构建与设计验收

- `pnpm run build` 保留原来的完整 Figma 前置门禁，需要本地原始导出和截图证据。
- `pnpm run audit:figma` 保留全部节点、源锁、资源和截图检查，没有因忽略文件而跳过任何检查。
- `pnpm run build:app` 用于只包含 Git 源文件的程序打包：图片压缩、类型检查和 Vite 构建；此命令不代表 Figma 验收通过。发布前仍按实施规范完成独立设计验收。
- 新机器可从 Git 构建应用；重新开展设计验收时，需要恢复本地源归档/证据，或从 Figma 重新提取并验证，不能把缺少证据当作通过。

对已经被 Git 跟踪的本地归档，使用 `git rm --cached` 取消跟踪并保留原文件。清理提交中看到的这类“删除”表示从仓库移除，不表示删除本地资料；现有 Git 历史未改写。
