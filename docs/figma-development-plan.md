# Figma 页面开发计划

本计划按既定页面顺序执行，所有页面遵循 `docs/figma-implementation-standard.md`。每个页面必须完成以下闭环后才能进入下一项：

1. 从 Figma Dev Mode 的 Layers 和右侧参数逐层提取，记录 Node ID、尺寸、层级、样式、资源和状态。
2. 复制/转换为 Vue 静态基线，完成桌面端和移动端 Figma 还原。
3. 接入路由、点击、Hover、Tab、弹窗、上传、匹配、表单和业务入口等交互逻辑。
4. 参考 Octagos 加入不改变静态布局的动效，并提供移动端及 `prefers-reduced-motion` 降级。
5. 在 Figma 桌面/移动尺寸截图核验，修正差异，补齐参数记录和验证证据。
6. 运行交互检查、溢出检查、类型检查和生产构建。

## 汇报与状态规则

- 每完成 2 个正式页面/状态汇报一次进度；汇报内容包含已完成项、截图核验结果、剩余差异和下一项。
- 同一路由的独立 Figma 状态按表格单独验收，不因主页面完成而跳过。
- `cost-generated` 只作为 Figma-to-Vue 流程试验，不替代正式 `/cost` 验收。
- 任何无法从 Figma 读取的值必须记录为“未解析”，不得用截图测量、经验值或猜测补齐。
- 未完成参数记录、交互逻辑、动效、桌面/移动截图核验中的任一项，页面状态不得标记为完成。
