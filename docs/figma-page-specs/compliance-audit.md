## 执行门禁

在任何页面或批次汇报为完成前，必须运行 `pnpm run audit:figma`。脚本会拒绝以下状态：`verified` 页面存在 `pending/unresolved` 参数、无独立 Figma 源帧、缺少桌面/移动验证证据、缺少交互/动效记录，或被标记为 Figma 合规阻塞。脚本失败时只能继续提取和修复，不能汇报完成。

### Figma-first 不可跳过顺序

页面执行必须严格遵守：`Figma 源帧全量层级清单 → 每个节点 Dev Mode 参数 → Node ID 到 Vue 映射 → 静态实现 → 交互/动效 → 桌面/390px/状态证据 → 门禁与构建`。未完成前一阶段不得进入下一阶段；聊天中的“记住”不构成完成证据。

### 汇报约束

- 只有 `pnpm run audit:figma`、类型检查、生产构建和 `git diff --check` 全部通过，页面才能汇报为完成。
- 任何 `pending`、`unresolved`、泛化 child 映射、缺少独立源帧或缺少截图/状态证据，均只能汇报为未完成或阻塞。
- “业务实现完成”与“Figma 还原完成”必须分开表述。
- 每次两页进度汇报必须列出实际通过的页面和仍被门禁拦截的页面，不得用总体完成率替代页面级证据。
