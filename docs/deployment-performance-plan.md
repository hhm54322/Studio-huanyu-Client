# 独立站访问性能与部署方案

本文保留2026-11-01的诊断与改造过程。**当前结果以[2026-11-03缓存与加速方案](site-speed-acceleration-20261103.md)及[发布记录](deployment.md)为准**：静态资源已改内容哈希/一年缓存，公共页面壳本地缓存已上线；两域名HTTP/2、匿名首页/牙科60秒边缘缓存、身份隔离及77项官方预热已生效。下文“未获得控制台证据”“30天缓存”等为历史状态。

## 已完成的代码优化

- 首页首图和 Logo 在 HTML 解析阶段请求，减少等待 Vue/CSS 才发现图片的瀑布；后续轮播图按顺序低优先级预热，保持 5 秒切换及仅图片 hover 暂停。
- 下方模块图片在接近视口时加载；图表和详情弹窗按需加载。保留 Figma 图源、尺寸、裁切和原有交互。
- 公共页头/页脚不再让其他页面下载整套首页源数据；共享坐标工具与医院源数据拆开，避免医生、信任、流程和工具包页引入无关医院数据。
- 当前桌面路由依赖在CSS阻塞前启动；图标合并为一个缓存包。医院详情、原始详情源数据和图表仅在打开弹窗后加载，首次传输量由约529KB降至217KB。
- 牙科详情仅在打开时加载，首次JS传输量由约245KB降至204KB；工具包6篇文章各自独立加载，默认页由约218KB降至155KB，直达某篇只请求该篇。当前文章提前请求、切换前准备数据及已加载缓存均已验证。
- 增加桌面公共页首次资源下载失败的受控恢复：同版本、同页60秒内最多重试一次，用户开始操作或页面已展示后不刷新；报告、后台及移动端不纳入自动恢复。该机制不能替代链路加速。
- 沿用 WebP 压缩和既有尺寸规则。本次发布准备中，134 张符合转换条件的图片合计由 72.3MiB 降为 9.7MiB；原件保留。此数字不是单页流量，已有优化图片没有重复计作新增收益。

前序构建13路由首屏/适用页脚对照最高nMAE0.0092%，本轮`20261101041000`对前序版最高0.00056%，无新增运行错误或横向溢出；非医院页不再请求医院源包。共享字体、医生科室筛选、全部医生详情、信任长文/手风琴和关闭恢复亦已回归。未改医疗报告生成、后台或现有接口；移动端按既定设计冻结。

## 现有部署判断

- 源站位于阿里云新加坡 `ap-southeast-1`，2 vCPU、约1.6GiB内存；本轮采样负载约0.26，可用内存约424MiB、Swap未使用、磁盘剩余约21GiB。当前未观察到 CPU 或磁盘容量瓶颈；内存余量适合持续观察。
- 主站已有阿里云 CDN，域名 CNAME 指向 CDN，响应为 Tengine。已实测香港缓存节点与首页图片 HIT，JS支持gzip；本轮公网浏览器实际仍协商HTTP/1.1。与前序记录不同，本轮显式禁用代理并指定`127.0.0.1`回环的生产SNI请求已协商HTTP/2，应继续核查CDN边缘协议，不能再把源站未开HTTP/2作为当前结论。尚未拿到云端配置，不能宣称所有地区或全球加速均已开通。
- 当前HTML为`no-cache`，版本文件不缓存，静态资源为30天缓存。首图已压缩到约71KB。本轮源站回环3路由HTTPS首字节约0.098–0.106秒，公网19地址约0.674–1.923秒、中位1.273秒；两者用于定位链路差异，不组成跨地区SLA或稳定改善率。证据为`artifacts/deployment/20261101080000/source-performance-direct.json`和`online/public-loading-qa.json`。

## 建议实施顺序

| 优先级 | 措施 | 配置与作用 | 何时实施 |
| --- | --- | --- | --- |
| P1 | 核对并优化现有 CDN | 核实国内及目标海外地区覆盖；开启可用的 HTTP/2、HTTP/3、Brotli；保留gzip回退；发布后预热首图、入口JS/CSS、字体与关键路由依赖，避免首批用户遇到冷缓存 | 首先做，优先利用现有服务 |
| P1 | 明确缓存规则 | 哈希JS/CSS/图片可长期缓存；同名可更新图片须版本化，或缩短缓存并在发布时刷新。HTML暂保留no-cache；若首字节仍慢，可对不含个人数据的公共HTML试点30–60秒边缘缓存，发布时主动刷新。`/api/`、上传资料、报告、专家工作台及鉴权响应不进入公共缓存 | 与CDN核查一并做，先灰度验证 |
| P1 | 建立按地区的验收 | 对中国电信/联通/移动、香港、新加坡及实际主要海外客群地区做冷缓存/热缓存测试；分别记录HTML首字节、LCP、INP、CLS、静态错误率和缓存命中率。没有真实用户数据时先用外部探测；监控不采集病例正文或用户资料 | 云端调整前后均测 |
| P2 | 静态文件迁至 OSS + CDN | 公共图片、字体、哈希JS/CSS放私有OSS并通过授权回源的CDN交付，减少ECS带宽/磁盘及发布压力；资源路径与跨域策略先在测试域验证。用户上传的病例资料仍走原鉴权链路 | 流量增大或发布运维压力出现时 |
| P2 | 按瓶颈选择 DCDN 或全球加速 | 先测试动态API、上传、会话等无法缓存请求。需要七层动态链路优化时评估全站加速DCDN；确有跨国网络问题时对动态入口试点GA。先单域/少地区A/B，不同时叠加多套加速而无法归因 | 目标地区API/上传持续慢时 |
| P3 | ECS扩容与任务隔离 | 正式推广前可将4核8GiB作为更稳妥容量基线；持续CPU高、内存不足或队列积压时优先升级/隔离报告任务。后续将AI/报告作业交给独立worker、队列，配合数据库连接池和对象存储 | 根据负载及推广计划，而非仅因图片加载慢就扩容 |

CDN解决公共静态内容的就近分发；GA主要改善指定动态入口的跨地域链路；扩容改善源站计算/内存容量。三者各自解决的瓶颈不同。对当前网站，优先顺序是**已有CDN配置与预热 → 地域实测 → 按实际瓶颈增加动态加速和容量**。

## 配置落地与回滚

1. 先导出现有CDN规则，记录加速范围、HTTPS协议、压缩、缓存、回源、证书及费用项。协议开关需要在CDN边缘开启；仅改源站Nginx不能让客户端自动使用HTTP/2。
2. 先启用可用的HTTP/2，再单独评估HTTP/3/Brotli；分别验证浏览器协商协议、`Content-Encoding`、缓存HIT及回退，保留每项前后实测。
3. 对首页等不含个人信息的公共HTML小范围试点30–60秒边缘缓存，浏览器保持重验证；API、病例上传、报告、审阅及鉴权路径继续禁止公共缓存。验证退出登录/权限变化时不会读到他人的资料。
4. 发布前用CDN官方预热能力准备新哈希JS/CSS、首图及字体，发布后只刷新公共HTML/版本入口；本机访问仅能预热当前命中的节点，不能冒充全网预热。
5. 每项调整先记录原值；若错误率或地区延迟升高，恢复原规则并刷新受影响的公共缓存。付费GA/DCDN与扩容先做试点和预算确认，不在现有CDN上盲目叠加。

本轮已有SSH部署权限，未获得CDN云控制台配置证据；因此代码与静态发布已执行，上述云端配置为实施方案，尚未声称开通。

## 流畅度验收口径

- 正常目标网络的真实用户第75百分位争取达到 LCP≤2.5秒、INP≤200ms、CLS≤0.1；慢网测试另外记录，不用均值掩盖慢地区。
- 公共HTML首字节以目标地区第75百分位≤800ms为优化目标；静态资源预热后应稳定命中CDN，发布不产生旧版本资源404。
- 首图不晚于首屏主要文字明显出现；轮播切换前图片已准备好，弹窗与滚动无连续卡顿。保持原设计及业务行为。
- 先用真实访问和地域探测定位问题，再决定是否购买付费加速或扩容；本轮未新购云产品、未修改DNS或扩大SSH权限。
